# AGENTS.md

Fluxpoint (repo directory `corne-hybrid`) is a Phase 0 hardware/firmware project: a low-profile Corne 3x6+3 split keyboard with ZMK, a right-half TrackPoint, and a Flutter configurator planned for Phase 4. Most of the repo is specification; the custom PCB, case, and final shield do not exist yet.

## Start here

- `docs/README.md` — documentation map. `docs/requirements.md`, `docs/architecture.md`, `docs/roadmap.md`, and the ADRs are the design source of truth.
- `.opencode/skills/<name>/SKILL.md` — project workflows (`fluxpoint`, `docs`, `zmk`, `kicad`, `cad`, `bringup`, `bom`). Load the matching skill before working in that area.
- `docs/automation.md` §7 and `.github/workflows/firmware.yml` — canonical firmware build commands.

## Verification

Run before committing; CI runs the same sequence on Python 3.12:

```bash
python tools/fluxpoint_cli.py check-docs
python tools/fluxpoint_cli.py check-config
python -m pytest -q tools/tests
```

- `check-config` and the tests need PyYAML: `python -m pip install -r tools/requirements.txt` (or `./tools/setup_dev.sh`, Arch-only).
- Single test: `python -m pytest -q tools/tests/test_cli.py::test_find_broken_links_detects_missing`.
- `check-docs` validates every local Markdown link outside the ZMK west workspace; broken relative links fail CI.

## Firmware

- `firmware/zmk-config` is the ZMK user config; `config/west.yml` pins ZMK v0.3.0.
- The documented build path is Docker (`zmkfirmware/zmk-build-arm:stable`); do not assume a host Zephyr toolchain is set up.
- `firmware/zmk-config/{zmk,zephyr,modules,optional,.west}` is generated by `west update` and gitignored. Do not edit it. After the first build, `west init -l config` fails; run `west update` instead or remove `.west` for a clean init.
- The baseline is the stock, **left-central** Corne shield with no TrackPoint. The final firmware is **right-central** (`fluxpoint_left`/`fluxpoint_right`) because the TrackPoint is on the right half. Do not treat the baseline as the final design.
- Keep 42 bindings per keymap layer. The pin map is not frozen; never invent matrix, TrackPoint, or display pins.
- Flash by copying the UF2 to the bootloader volume (double-tap reset); copy `settings_reset` first for stale settings.

## Scope boundaries

- `hardware/{pcb,case}`, `firmware/{modules,dongle}`, and `software/configurator` contain README placeholders only. Do not assume KiCad, FreeCAD, or Flutter project files exist.
- `docs/bom.md` is the procurement source of truth. Do not purchase parts; update the BOM and ask.
- Do not commit generated fabrication/build artifacts (Gerbers, STL, STEP, UF2, HEX).
- Human review is required before ordering PCBs, flashing new hardware, or making safety-critical changes.

## Conventions

- Architecture, scope, or interface changes need an ADR in `docs/decisions/` (template in its README).
- Documentation and identifiers are English; measurements use mm and note confidence.
- Preserve licensing and attribution: hardware CERN-OHL-S-2.0, firmware MIT, docs CC BY 4.0; see `NOTICE`.
